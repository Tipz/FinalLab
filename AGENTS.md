# Работа над «Вместе в путь»

Правила адаптированы из ДЗ 2 (Home Services Dashboard, Отчет/rules.md) к текущей
клиент-серверной реализации ДЗ № 5.

- Основа поведения: docs/technical_specification.md, docs/backend_requirements.md и обязательные US-01–US-10 в docs/user_stories.md.
- Стек: C#, .NET 10, standalone Blazor WebAssembly, MudBlazor, ASP.NET Core Minimal API, EF Core/Npgsql и PostgreSQL.
- Together.Core содержит модель, расчёты и валидацию без зависимости от UI, браузера и базы данных. Together.Contracts содержит DTO и маршруты API. Together.Client содержит компоненты, управление экраном, API-клиент и адаптер старой IndexedDB только для добровольного импорта. Together.Api отвечает за Identity, владение данными, транзакции и PostgreSQL.
- Не добавлять прикладные роли, Interactive Server, SQLite или автоматическую отправку локальных данных. В рамках ДЗ № 6 разрешён ровно один социальный вход — OAuth 2.0 через Яндекс ID как дополнительный способ аутентификации; существующие регистрация и вход по паролю сохраняются. Другие OAuth-провайдеры не входят в утверждённый объём.
- Пользовательский ввод выводить как текст. Внешние ссылки допускают только абсолютные http/https и открываются с noopener noreferrer.
- Считать расходы в целых копейках; различать null и ноль. Даты считать через DateOnly.
- Сохранённые данные заменять в интерфейсе только после успешного ответа API и серверной транзакции. Старую IndexedDB не очищать автоматически.
- При `409 Conflict` не терять черновик; перед его отбрасыванием спрашивать подтверждение в интерфейсе.
- UI на русском, холодная палитра концепции 3, сравнение перед карточками. Использовать MudBlazor и семантические HTML-элементы.
- Не отправлять поездки, возраст детей или заметки в сторонние сервисы; они передаются только собственному backend. Тесты и скриншоты используют вымышленные данные.
- Секреты и строки подключения получать из переменных окружения или secret store, не включать их в Git, Docker image, логи или Blazor bundle.
- Production-образ публикуется в `ghcr.io/tipz/together` для `linux/amd64` и `linux/arm64`. Учебный production-стенд работает на локальной машине `192.168.1.26` за существующими Traefik и локальным центром сертификации. Подготовленный deployment job для self-hosted GitHub runner отключён в универсальном workflow, поэтому текущее production-развёртывание выполняется оператором через `docker-compose.deploy.yml` по immutable digest. Перед запуском приложения миграции выполнять отдельным одноразовым заданием; ключи Data Protection хранить вне writable layer контейнера.
- Не менять несвязанные файлы и исходные материалы пользователя. Избегать лишних зависимостей и абстракций.
- Для нетривиальных изменений запускать подходящие тесты. Перед сдачей: Release-сборка, оба xUnit-проекта и актуальный `--backend-smoke`; старый двухбраузерный IndexedDB-набор относится к ДЗ № 4.
- Документировать фактические команды, результаты и ограничения. Не выдавать неисполненные проверки за успешные.
