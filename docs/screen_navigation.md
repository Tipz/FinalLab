# Три основных экрана

Изменение от 14.10.2026 устраняет неоднозначность подсчёта экранов. Основной
пользовательский путь: **«Мои поездки» → «Варианты поездки» → «Сравнение»**.

Интерфейс следует концепции [«План поездки»](ui_concepts/03-analytical.html):
холодная сине-серая палитра, таблица перед карточками на экране сравнения,
навигация с обозначением текущего экрана на компьютере и телефоне.

| Экран | Маршрут | Действия и содержание |
| --- | --- | --- |
| Мои поездки | `/` | Список сохранённых поездок, даты, состав семьи, количество вариантов, создание и редактирование параметров, открытие вариантов или сравнения |
| Варианты поездки | `/trips/{id}/variants` | Все карточки одной поездки, расходы и уточнения, добавление/редактирование/удаление, выбор вариантов и переход к сравнению |
| Сравнение | `/trips/{id}/comparison` | Критерии, таблица выбранных вариантов, затем их карточки с деталями и уточнениями; возврат к выбору вариантов |

`{id}` — GUID поездки. Это три отдельных маршрутизируемых Razor-страницы с
общим компонентом `TripWorkspace`, который сохраняет прежние операции API,
редакторы и обработку конфликтов. `/login` обслуживает вход и регистрацию;
редакторы остаются диалогами. Страница «не найдено» служебная и в число основных
экранов не входит.

Навигация отмечает текущий экран через `aria-current="page"`. На широком
экране она находится сбоку, на узком — над содержимым. Если есть сохранённые
поездки, все три пункта доступны и на главной: варианты и сравнение открывают
первую поездку из списка. На страницах конкретной поездки меню открывает её
разделы. Без сохранённых поездок пункты меню также остаются ссылками: `/variants`
и `/comparison` открывают соответствующий раздел с предложением создать поездку
или добровольно импортировать найденные локальные данные. Если поездки уже есть,
эти маршруты открывают первую доступную поездку. Неизвестный GUID по-прежнему не
подменяется существующей поездкой.
Обе страницы поездки позволяют менять поездку переключателем, сохраняя раздел.
Прямые ссылки и перезагрузка читают данные пользователя из API и сохраняют
раздел и идентификатор из URL. Неизвестный или недоступный идентификатор показывает
«Поездка недоступна» с возвратом к списку и не подменяется другой поездкой.

На первом открытии пустого списка создаётся прежний вымышленный пример, который
показывается в списке. Новая поездка открывает свои варианты только после
успешного сохранения. В пустом сравнении можно перейти ко всем карточкам или
создать вариант; после создания открывается экран вариантов, где его можно
выбрать. При снятии выбора вариант остаётся в общем списке карточек.

Переход с открытым редактором требует подтверждения отбрасывания правок;
отмена оставляет форму и черновик на месте. Во время сохранения переходы
блокируются. Для `409 Conflict` сохраняется отдельное подтверждение загрузки
актуальных данных. Выбранные варианты и критерии хранятся независимо для каждой
поездки на сервере. IndexedDB по-прежнему используется только для добровольного
импорта. Метрика получает `/trips/variants` или `/trips/comparison`, без GUID
поездки, query string и fragment.

## Фактические проверки

Локально выполнены следующие команды:

```powershell
dotnet build Together.slnx --configuration Release --no-restore
dotnet test tests/Together.Tests/Together.Tests.csproj --configuration Release --no-build --no-restore
dotnet test tests/Together.Api.Tests/Together.Api.Tests.csproj --configuration Release --no-build --no-restore
dotnet format Together.slnx --verify-no-changes --no-restore
git diff --check
```

Release-сборка прошла без ошибок и предупреждений. `Together.Tests` — 66/66,
`Together.Api.Tests` — 25/25. Проверки форматирования и diff прошли.
Новые bUnit-сценарии проверяют три разных экрана, переходы, прямое открытие
обоих разделов конкретной поездки, независимость выбранных вариантов и
критериев, недоступный идентификатор и сохранение черновика при отменённом
переходе, подтверждённое закрытие редактора и переход к входу при истечении
сеанса во время записи. Тесты аналитики проверяют удаление GUID из обоих маршрутов.
bUnit использует вымышленные ответы HTTP; API-тесты используют тестовую
EF InMemory. Эти проверки не подтверждают работу PostgreSQL или реального
браузера.

Актуальный `--backend-smoke` расширен проверками всех трёх экранов, истории
«Назад»/«Вперёд», перезагрузки и прямых ссылок, создания второй поездки,
пустого сравнения, независимости критериев и навигации на ширинах 360, 768 и
1440 CSS-пикселей. В браузере проверены отмена и подтверждение перехода «Назад»
с открытым черновиком. Прежние сценарии бюджета, ошибок 503/409 и выхода сохранены.
Первый запуск на `http://localhost:8080` завершился `ERR_CONNECTION_REFUSED`,
так как backend ещё не был запущен. Затем найдены переносимые PostgreSQL и
Chromium, подготовлен отдельный локальный стенд с вымышленными данными.

## Проверка в настоящем браузере

14.10.2026 запущены PostgreSQL 17.11 и опубликованные текущие Release-сборки
клиента и API. Для проверки создана отдельная база; существующие данные не
использовались. Настройки соединения, HTTP cookie и Data Protection передавались
через переменные окружения процесса. Ключи сохранялись отдельно от опубликованного
приложения. Обе миграции выполнены отдельным процессом перед запуском API.
Выполнены команды публикации:

```powershell
dotnet publish src/Together.Client/Together.Client.csproj --configuration Release --no-restore -o artifacts/screen-navigation/client
dotnet publish src/Together.Api/Together.Api.csproj --configuration Release --no-restore -o artifacts/screen-navigation/api
Copy-Item -Path artifacts/screen-navigation/client/wwwroot/* -Destination artifacts/screen-navigation/api/wwwroot -Recurse -Force
```

Из каталога опубликованного API выполнены `dotnet Together.Api.dll --migrate`
и затем `dotnet Together.Api.dll --urls http://localhost:5188`. Нативные `initdb`,
`pg_ctl` и `createdb` подготовили временный PostgreSQL, доступный только по loopback.
Docker для этой локальной проверки не использовался.

Браузер запущен с видимым окном, а не только в headless-режиме:

```powershell
$env:APP_URL = 'http://localhost:5188'
$env:BROWSER_EVIDENCE_DIR = 'artifacts/screen-navigation/backend'
dotnet run --project tests/Together.BrowserTests --configuration Release --no-restore -- --backend-smoke --headed
Remove-Item Env:APP_URL,Env:BROWSER_EVIDENCE_DIR
```

Результат: **PASS**, код выхода 0, Chromium **151.0.7922.34**.
Проверены регистрация/выход, все три экрана, прямые ссылки, перезагрузка,
история браузера, независимость поездок и критериев, снятие и восстановление
выбора среднего варианта, переключение критерия «Кухня», пустое сравнение,
сохранение лимита/резерва и уточнений, черновики при 503 и настоящем конфликте
revision 409, подтверждение отбрасывания правок, клавиатура, ширины 360/768/1440
и форма при масштабе 200%. Неожиданных JavaScript-ошибок и ошибок консоли
в успешном запуске не было. Мобильные скриншоты всех трёх экранов просмотрены.

Первый запуск на PostgreSQL выявил 500 при отключении критерия: уникальный индекс
`(TripId, Position)` конфликтовал с заменой списка в одном `SaveChanges`.
Настройки сравнения теперь заменяются двумя записями внутри общей транзакции:
сначала удаление старых списков с проверкой revision, затем вставка новых.
Успех возвращается после commit. Проверки владения и ответ 409 сохраняются;
новая миграция не требуется. Повторный браузерный запуск подтвердил переключение
вариантов и критериев без 500. Добавлен API-тест замены, перестановки и очистки
критериев с проверкой устаревшей revision. Также указан существующий PNG как
favicon, чтобы браузер не запрашивал отсутствующий `/favicon.ico`.

выводились как `span`, даже когда сохранённые поездки уже были загружены.
