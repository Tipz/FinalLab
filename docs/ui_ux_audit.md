# UI/UX-аудит и точечная доработка — 14.10.2026

Проверены текущие исходники standalone Blazor WebAssembly и MudBlazor,
AGENTS.md, technical_specification.md, backend_requirements.md и user_stories.md.
Осмотр выполнен в Chromium 151.0.7922.34 на локальном приложении с настоящим
API и отдельной PostgreSQL-базой. Использованы только вымышленные аккаунты,
поездки и варианты. Для проверки блока аналитики задан тестовый номер счётчика;
согласие не предоставлялось, запросы к Метрике в инструменте аудита блокировались.

## Подтверждённые проблемы и исправления

| Приоритет | Наблюдение | Изменение |
| --- | --- | --- |
| 1 | Фиксированный блок аналитики накрывает содержимое карточек, а на телефоне занимает значительную часть экрана | Блок перенесён в обычный поток под страницей; состояния согласия и действия сохранены. Общая оболочка сохраняет центрирование формы входа |
| 1 | Кнопки длинной формы уходят за пределы диалога; для закрытия нужно возвращаться к началу | Общий EditorDialog получил прокручиваемую область; заголовок и закрытие остаются сверху, сохранение и отмена закреплены снизу |
| 2 | После появления ошибки возраста кнопка «Убрать» опускается ниже поля | Кнопка выровнена относительно строки ввода, независимо от текста ошибки |
| 2 | На 768 px три карточки идут в одну широкую колонку и излишне растягивают страницу | Две колонки сохраняются до 720 px; на телефоне остаётся одна |
| 3 | Мелкие подписи бюджета и действия карточки затрудняют чтение | Подписи увеличены до 13 px, кнопки карточек — до 14 px; отступы полей и заголовков редакторов приведены к единому ритму |
| 3 | Длинное направление сжимает и смещает переключатель «Сравнить» | Переключатель не сжимается и выравнивается у верхнего края; направление переносится в оставшейся ширине |
| 3 | Secondary у MudBlazor оставался стандартным фиолетовым | Secondary связан с уже используемым холодным серо-синим цветом темы |

Сохранены русский язык, холодная палитра концепции 3, существующие страницы,
навигация и расположение таблицы перед карточками. Домен, API, расчёты, правила
сохранения и обработка конфликтов не изменены.

## Браузерная проверка

До и после правок осмотрены вход, список поездок, варианты, сравнение и оба
редактора при ширинах 360, 768 и 1440 px. Дополнительно проверены:

- Название поездки из 100 символов, название и направление варианта из 150
  символов без пробелов, длинное описание жилья.
- Пустые варианты и сравнение, незаполненные обязательные поля, отрицательный
  расход, неверные учётные данные.
- Отсутствие горизонтального переполнения документа, сохранение внутренней
  прокрутки таблицы и её закреплённых заголовков.
- Видимость закрытия, сохранения и отмены в длинных редакторах на трёх ширинах.
- Последовательный Tab через поля длинной формы при 360 × 640 px:
  сфокусированные поля не скрываются заголовком или закреплёнными действиями.
- Клавиатурный переход между полями и Escape в диалоге при 740 × 360 px.
- Отказ от аналитики и доступность её настройки внизу страницы без перекрытия
  рабочих блоков.

Актуальный backend smoke проверил регистрацию и выход, три основных экрана,
прямые ссылки и историю, независимость поездок, выбор вариантов и критериев,
лимит и резерв, уточнения, восстановление после перезагрузки, ошибки записи 503,
реальный конфликт 409, сохранение черновика и подтверждение его отбрасывания,
мобильную навигацию, клавиатуру и форму при масштабе 200%.

Два первых запуска smoke выявили гонку самого теста: после нажатия
«К вариантам поездки» он обращался к checkbox, пока ещё отображались карточки
сравнения. Добавлено ожидание заголовка экрана, трёх карточек и снятого выбора
среднего варианта. Итоговый запуск прошёл полностью; проверки не исключались.

## Фактически выполненные команды и результаты

Подготовка стенда: создана отдельная локальная PostgreSQL-база, строка подключения
и Data Protection path переданы через окружение процесса. Миграции выполнены
отдельным одноразовым запуском до старта API:

```powershell
dotnet src/Together.Api/bin/Release/net10.0/Together.Api.dll --migrate
dotnet publish src/Together.Client -c Release --no-restore -o artifacts/ui-audit/client
dotnet src/Together.Api/bin/Release/net10.0/Together.Api.dll --urls http://localhost:5198 --webroot "$PWD/artifacts/ui-audit/client/wwwroot"
```

После перепубликации frontend сервер перезапущен, чтобы он использовал актуальные
статические ресурсы. Все команды ниже завершились с кодом 0:

```powershell
dotnet build Together.slnx -c Release --no-restore
dotnet test tests/Together.Tests/Together.Tests.csproj -c Release --no-build --no-restore
dotnet test tests/Together.Api.Tests/Together.Api.Tests.csproj -c Release --no-build --no-restore
dotnet format Together.slnx --verify-no-changes --no-restore

$env:APP_URL='http://localhost:5198'
$env:BROWSER_EVIDENCE_DIR="$PWD/artifacts/ui-audit/backend-smoke-final"
dotnet run --project tests/Together.BrowserTests -c Release --no-build --no-restore -- --backend-smoke

dotnet run --project artifacts/ui-audit/Audit.csproj -- after
git diff --check
```

- Release: 0 ошибок, 0 предупреждений.
- Together.Tests: **66/66**.
- Together.Api.Tests: **25/25**.
- Format и проверка diff: прошли.
- Backend smoke: **passed: true**, Chromium 151.0.7922.34.
- Локальный инструмент аудита: проверки переполнения, длинных названий,
  ошибок, видимости действий и клавиатурного фокуса прошли.

Инструмент аудита и полные логи находятся в исключённом из Git каталоге
`artifacts/ui-audit`. Он создан только для этого осмотра и не добавляет
зависимостей приложению. Итог smoke сохранён также в
[backend-browser-results.json](evidence/ui-ux-audit-20261014/backend-browser-results.json).

## Ограничения

Docker отсутствует в окружении: smoke выполнен на опубликованном frontend,
настоящем ASP.NET Core API и изолированном PostgreSQL, без проверки контейнеров.
Публикация frontend сообщает об отсутствии локального wasm-tools workload;
браузерные проверки опубликованного результата прошли. Firefox, Safari,
физические мобильные устройства и экранный диктор в рамках этого аудита не
проверялись. Изменения не развёрнуты на публичном сайте.
