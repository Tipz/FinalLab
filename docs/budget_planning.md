# Лимит бюджета, резерв и уточнения

Дата реализации и проверки: 12.10.2026. Изменение дополняет US-01–US-10 историями
US-14 и US-15. Последующее production-развёртывание выполнено 13.10.2026:
[публичный стенд и проверки](manual_production_deployment.md).

## Поведение для пользователя

В «Параметрах поездки» задаются лимит бюджета и резерв. Лимит относится ко всей
семье на весь период: пустое поле — не задан, 0 — нулевой лимит. Допустимый диапазон
0–100 000 000 ₽ с точностью до копейки. Резерв — целый процент 0–100, по умолчанию 0.
Изменения записываются кнопкой «Сохранить».

Для каждого варианта отдельно вычисляются:

1. Сумма известных расходов из шести статей.
2. Резерв: сумма × процент / 100, округлённая вверх до целой копейки.
3. Итог с резервом и разность между лимитом и итогом.

Пример: расходы 130 000 ₽, резерв 10%, лимит 150 000 ₽ дают резерв 13 000 ₽,
итог 143 000 ₽ и остаток 7 000 ₽. Альтернативные варианты не суммируются.

| Состояние | Отображение |
| --- | --- |
| Полный, проверенный бюджет ниже лимита | «До лимита осталось» и сумма |
| Итог равен лимиту | «Бюджет равен лимиту. Свободного остатка нет» |
| Итог выше лимита | Превышение и сумма |
| Неполный бюджет ниже лимита | Известные расходы и предупреждение, что итог может превысить лимит |
| Известная часть уже выше лимита | «Уже выше лимита по известным расходам» |
| Расходы требуют проверки | Отметка проверки; положительный остаток не объявляется подтверждённым |
| Все расходы неизвестны | «Бюджет не заполнен»; предложение заполнить расходы, если задан лимит |
| Лимит не задан | Расходы и резерв без оценки остатка |

Расходы и неизвестные суммы сохраняют прежний смысл: `null` не равен 0.
Смена лимита/резерва не меняет статьи расходов и не устанавливает отметку
пересмотра. Изменение дат/состава семьи по-прежнему требует ручной проверки.

Карточка содержит раскрываемый список «Что уточнить · N». Сначала перечисляются
отсутствующие расходы, затем напоминание о пересмотре, затем неизвестные
характеристики включённых критериев. Расходы показываются независимо от критерия
«Бюджет». Значения 0 и «Нет» не создают уточнение. При пустом списке блок скрыт.

«Заполнить» открывает редактор нужного варианта с фокусом на соответствующем поле.
После успешного сохранения заполненного значения пункт исчезает. Для снятия
напоминания о пересмотре нужна явная отметка «Расходы проверены».

При ошибке сервера или `409` черновик остаётся в форме, а карточка показывает
сохранённые данные. Загрузка актуальных данных с отбрасыванием правок требует
подтверждения. Отказ от подтверждения оставляет форму открытой.

## Реализация

- `Together.Core`: поля Trip/TripDraft, валидация, `Budget.Assess` и
  `VariantClarifications.For`. Расчёт не зависит от браузера и БД.
- `Together.Contracts`: поля `budgetLimitKopecks` и `reservePercent` в запросе
  поездки и ответе. Используются существующие POST/PUT маршруты поездки.
- `Together.Api`: сохранение настроек с проверкой владельца/revision,
  серверная валидация и CHECK-ограничения PostgreSQL.
- `Together.Client`: формы, оценки в карточках/таблице/предпросмотре,
  список уточнений, переход и фокус через существующий JS-адаптер UI.
- Миграция `20261012132837_TripBudgetSettings`: nullable bigint для лимита,
  integer с DEFAULT 0 для резерва. Старые записи и связи сохраняются.
- Старые Workspace из IndexedDB принимаются без новых полей: лимит null,
  резерв 0. Импорт остаётся добровольным; локальная копия не изменяется.

Производные суммы и список уточнений отдельно в БД не хранятся. Новых зависимостей
и сторонних интеграций нет. Условия отмены бронирования не входят в эту версию.
